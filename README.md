## 🎯 Про проєкт SkyGuard

**SkyGuard** — це інформаційна система керованого обміну геопросторовими та статусними даними про захисні споруди цивільного населення в режимі реального часу під час загроз та повітряних тривог.

### Ключові принципи Data Governance by Design у системі:
1. **Керований обмін (Governed Exchange):** чітке розмежування ролей Постачальників (ДСНС, балансоутримувачі, волонтери) та Споживачів (мешканці, екстрені служби).
2. **Чотирирівнева класифікація даних:**
   * *Public (Публічні):* адреси, офіційна місткість, загальний статус укриття.
   * *Internal (Внутрішні):* телеметрія електронних замків (Smart Lock), журнали оглядів.
   * *Confidential (Конфіденційні):* контакти комендантів, оперативні зведення ДСНС.
   * *Personal / Sensitive (Персональні):* точні GPS-координати переміщення громадян під час тривоги.
3. **Керування згодою (Consent Management):** збір персональних геоданих виключно за явною інформованою згодою користувача (відповідно до ст. 11 ЗУ «Про захист персональних даних»).
4. **Контроль якості даних (Data Quality Rules):** краудсорсинговий статус верифікується за правилом геозони (користувач повинен знаходитися на відстані $\le 100$ м від укриття за формулою гаверсину).
5. **Незмінний журнал аудиту (Cryptographic Audit Trail):** автоматична фіксація кожної транзакції (хто, коли, яку дію виконав і з яким результатом) із криптографічним хешуванням подій (SHA-256).

## ⚡ Організація розробки (Scrum Framework)

Проєкт виконується за гнучкою методологією **Scrum** у системі **Jira** за **3 тижневі спринти** (загальна оцінка беклогу — **63 Story Points**, 18 задач):

* **Sprint 1 (Тиждень 1) — 23 SP:** *Ініціалізація, Формулювання вимог (Use Cases), фундамент Data Governance (RBAC, класифікація), аналіз PRESTCOM/SWOT.*
* **Sprint 2 (Тиждень 2) — 24 SP:** *UML-архітектура (Class, Activity, Sequence), Матриця Захмана 6×6, інтерактивний UI у Figma та API прототипу.*
* **Sprint 3 (Тиждень 3) — 16 SP:** *Тестування безпеки (позитивне + негативне 403 Forbidden), зведення 12 розділів підсумкового звіту, демо-відео та презентація до захисту.*

## 📋 Обов'язковий сценарій демонстрації прототипу (7 кроків)
1. **Автентифікація:** вхід під певною роллю користувача.
2. **Згода (Consent):** фіксація згоди на обробку геолокації.
3. **Валідація якості:** перевірка відстані клієнта до укриття ($\le 100$ м).
4. **Успішний обмін:** оновлення статусу укриття (HTTP 200 OK).
5. **Аудит транзакції:** додавання незмінного запису в `audit_log`.
6. **Сповіщення споживача:** оновлення карти укриттів.
7. **Обов'язковий негативний сценарій:** спроба зміни статусу неавторизованим користувачем $\rightarrow$ блокування доступу **HTTP 403 Forbidden** $\rightarrow$ фіксація інциденту порушення безпеки в лозі аудиту.
